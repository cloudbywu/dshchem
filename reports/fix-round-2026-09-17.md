# dshchem 修复推进报告

- **日期**：2026-09-17
- **依据**：`reports/code-review-2026-09-17.md`（同批次审阅）
- **范围**：`packages/dsh-chem-core`、`packages/dsh-tool-chem`、`test/` 及配套文档

## 1. 修复清单

| 编号 | 问题 | 修复 |
|---|---|---|
| H1 | `chem_props` 的 `iupac: true` 恒触发 harness `ToolOutputError`（RDKit 无 `MolToIUPACName`，返回 `iupacName: null` + 未声明 `iupacError`） | **移除失效的 IUPAC 功能**：引擎删除该分支；工具删除 `iupac` 参数、`iupacName` schema 与渲染分支；服务 `props(smiles)` 简化。IUPAC 名改由 `chem_pubchem` 提供（工具描述已指向） |
| H2 | 配方库对 `null` 字段必失败（真实账本 44 条中 21 条 `project: null`） | 引擎侧新增 `normalizeRecipe`：读取时丢弃 null/缺失可选字段并补全必需字段；写入时不落 `null`；`recipeSave` 返回归一化记录 |
| H3 | 测试从不校验输出 schema（根因） | `test/integration.mjs` 对**每个**工具的返回值执行 harness 同款 `validateJsonSchemaValue`，违约即失败；`chem_pdf` 不再跳过，一并校验 |
| H4（闸门新捕获） | `chem_papers` 成功路径返回 `error: null` → `"value.error" must be a string` | `papersSearch` 成功分支不再返回 `error` 键；`test/benchmark.mjs` 两处断言原本写死 `error === null`（把缺陷当契约），改为 `error === undefined` |
| M1 | 引擎响应序列化在 try 之外、未禁 NaN | 新增 `_json_safe`（NaN/Inf→null，numpy 标量→Python 标量）与 `_emit`（序列化异常也回结构化 JSON），统一走 `allow_nan=False` |
| M2 | 空请求/未知 op 返回 1，违背「始终 exit 0」契约 | 两处改为 `return 0` |
| M3 | `op_enumerate` 先物化整个笛卡尔积 | 改为按 `itertools.islice` 惰性取 `maxProducts` 个，组合总数由各 R 组长度相乘快速得出（实测 4.096×10⁹ 组合 0.17 s 返回 `truncated: true`） |
| M4 | `op_screen` 的 `ADMETModel()` 在 stdout 重定向之外 | 构造与 predict 一并置于 `redirect_stdout` 内 |
| M5 | `op_pdftext` 无 try/finally；页数/字符数未校验 | `try/finally` 关闭文档；`maxPages∈[1,500]`、`maxChars∈[1,5e6]` 夹取 |
| M6 | 硬编码 `C:/Users/cloud/...` 与未校验数值参数 | aizynth/vina 默认路径改为 `os.path.expanduser("~")` 派生（env 覆盖不变）；`cutoff∈(0,1]` 校验、`mcs timeout∈[1,300]`、`dock exhaustiveness∈[1,64]`、`xtbTimeoutMs≥1` 夹取 |
| 低 | `OPS` 字典重复定义、docstring 只列 6 个 op | 删除失效的第一份 `OPS`；docstring 列全 19 个 op |
| 文档 | README 工具数写 11、`dsh-tool-chem` README/package.json 写 4 个工具、工具表过时 | 统一为 **24 个**；README 工具表补全 24 行；`chem_props`/IUPAC 说明改为指向 `chem_pubchem` |

## 2. 验证

- **schema 闸门首跑即捕获 H4**：`chem_papers output violates its schema: "value.error" must be a string`——证明闸门确实把此类缺陷从「运行时被 harness 拒绝」变为「测试失败」。
- **集成测试全绿**：`node test/integration.mjs` 退出码 0，24 个工具全部通过通用 schema 校验与既有回归断言（含 dock 9 poses/-11.91 kcal·mol⁻¹、admet 104 端点、aizynth 有效反应树、screen 排序）。
- **评测基准全绿**：`node test/benchmark.mjs` → **107 passed, 0 failed**。
- **真实账本验证**：44 条配方（含 21 条遗留 `null`）经 `chem_recipe_list`/`_search` 输出零 schema 违约；省略 `smiles`/`project` 的 `chem_recipe_save` 不再包含这两个键。
- **引擎协议验证**：空请求与未知 op 均 exit 0 并回结构化 JSON；`props` 不再含 IUPAC 键；超小/负 `maxPages` 被夹取后正常提取；非法 `cutoff` 返回结构化错误。

## 3. 兼容性说明

- **破坏性变更**：`chem_props` 移除 `iupac` 入参（该路径从未可用）；`props` 服务签名由 `(smiles, options)` 变为 `(smiles)`。
- **行为不变**：其余 23 个工具的入参与输出字段未变；配方库读取对历史数据向后兼容。
- 引擎（.py）经 junction + 每请求 spawn 即时生效；`lib/index.js` 改动需重启 dsh 才在宿主体内生效。

## 4. 仍未处理（诚实记录）

- `test/benchmark.mjs` 未接入统一 schema 闸门（集成测试已覆盖全部 24 个工具）。
- 测试与工具描述中仍有 `C:/Users/cloud/...` 受体/报告路径（引擎默认值已改，测试用例仍写死，属可移植性而非功能问题）。
- `chem_props` 的 IUPAC 需求若要满足，需接 PubChem 或装第三方 IUPAC 命名器；当前由 `chem_pubchem` 覆盖。
